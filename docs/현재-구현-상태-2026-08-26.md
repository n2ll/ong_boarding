# 현재 구현 상태와 다음 로드맵

> 마지막 코드 대조: 2026-08-26
> 이 문서는 과거 기획 체크리스트를 현재 할 일로 오인하지 않기 위한 요약이다. 운영 DB의 마이그레이션 적용 여부와 Vercel 환경변수 값은 저장소만으로 확인할 수 없으므로 별도로 표시한다. 제품 전략의 배경은 [`PRODUCT_DIRECTION.md`](../PRODUCT_DIRECTION.md), 상세 동작은 [`기능설명서.md`](./기능설명서.md)를 본다.

## 한눈에 보는 상태

|---|---|---|

## 현재 릴리스 우선순위

### 1. 운영 검증 게이트

- 운영 Supabase에 2026-07·08 멱등성/복구/동의 마이그레이션이 적용됐는지 대조한다.
- Vercel의 `CRON_SECRET`, Supabase Auth 가입 차단·허용 이메일, Slack 전역 OFF 값을 확인한다.
- 실발송을 반복하지 않는 통제된 1건으로 지원 접수 → 인입 답장 → 공고 귀속 → 매니저 응대까지 스모크 테스트한다.
- 공급자 결과 불명 건이 재발송되지 않고 사람 확인 대상으로 남는지 확인한다.

### 2. 매니저 운영 완성도

- 이번 배치의 공고 집계 페이지 처리·오류 표면화가 대량 데이터에서도 누락 없이 동작하는지 검증한다.
- 다공고 상황에서 화면에 표시한 공고 맥락과 문자 발송·답장 귀속이 끝까지 같은지 회귀 검증한다.
- 이번 배치의 공고 등록·수정 초안 보존, 이탈 경고, 생성·수정 검증 일치를 검증하고 데스크톱 키보드 흐름을 마감한다.

### 3. 신뢰성·운영 자동화

- 주요 지원·발송·상태 전이를 가능한 범위에서 DB 원자 연산으로 수렴하고 복구 큐의 관측성을 높인다.
- 핵심 사용자 흐름 E2E와 CI, 운영 오류·지연 모니터링을 추가한다.
- 공용 계정 파일럿을 벗어날 때 사용자별 권한과 감사 추적을 설계한다.

### 4. 제품 확장

- 운영 데이터가 쌓인 뒤 `shift_request`·웨이브 발송·신뢰 점수·충족 시간(TTF) 지표를 구현한다.
- 옹매니징 정산 대조를 이행 근거로 고도화하되, 외부 TMS가 없으면 알 수 없는 운행 지표를 제품 수치처럼 단정하지 않는다.

## 문서 해석 규칙

- `PRODUCT_DIRECTION.md` §5~6의 날짜가 붙은 체크리스트와 인터뷰 결론은 **의사결정 이력**이다. 현재 미완료 목록은 이 문서가 우선한다.
- ‘코드·마이그레이션 있음’은 운영 DB 적용 완료를 뜻하지 않는다.
- 지원자의 관심·가능 응답·정보 제출은 근무 확정이나 배정이 아니다. 확정은 매니저가 한다.
