> 마지막 코드·운영 설정 대조: 2026-08-31
> 이 문서는 과거 기획 체크리스트를 현재 할 일로 오인하지 않기 위한 요약이다. 운영 DB와 Vercel 설정의 확인 결과는 값 자체를 기록하지 않고 존재·상태만 표시한다. 제품 전략의 배경은 [`PRODUCT_DIRECTION.md`](../PRODUCT_DIRECTION.md), 상세 동작은 [`기능설명서.md`](./기능설명서.md)를 본다.

## 현재 릴리스 우선순위

### 1. 운영 검증 게이트

- **완료:** 운영 Supabase에서 2026-07·08 멱등성/복구/동의 핵심 테이블·컬럼과 외부 호출형 RPC 존재를 대조했다.
- **부분 완료:** Vercel `CRON_SECRET` 존재, Supabase Auth 가입 차단, Slack 전역 OFF를 확인했다. `ADMIN_ALLOWED_EMAILS` 반영만 남았다.
- 실발송을 반복하지 않는 통제된 1건으로 지원 접수 → 인입 답장 → 공고 귀속 → 매니저 응대까지 스모크 테스트한다.
- 공급자 결과 불명 건이 재발송되지 않고 사람 확인 대상으로 남는지 확인한다.

### 2. 매니저 운영 완성도

- **코드 완료:** 공고·지원자·대화·Pipeline의 전체 페이지 처리, 보조 조회 오류 표면화, 발송 전 안전 조회의 fail-closed 동작을 추가했다.
- **코드 완료:** 다공고 상황의 공고 맥락 유지, 전화번호 단위 수신거부·중복·피로도 판정, 외부 모집 전용 공고의 내부 안내 제외를 추가했다.
- **코드 완료:** 계정별 공고 초안 보존과 다중 탭 충돌 감지, 교체·삭제 확인, Pipeline 대량 발송 모달 스크롤, 대화 갱신 오류 중복 안내를 마감했다.
- **검증 완료:** 2026-08-31 기준 전체 테스트 786개(통과 782·의도적 skip 4), TypeScript, ESLint, 프로덕션 빌드를 통과했다. 데스크톱 `/jobs`·`/pipeline`·`/live`와 모바일 `/apply`를 실제 브라우저에서 확인했고 콘솔 오류 없이 주소 검색·차종 조건부 입력·정산계좌·문자 수신 선택을 확인했다.
- 지원자 목록의 최신 조회가 실패하면 Jobs는 후보 없음으로 축약하지 않고 재시도를 표시하며, Pipeline은 기존 목록을 읽기 전용으로만 남기고 문자·후보등록·노출·단계변경을 닫는다.

### 3. 신뢰성·운영 자동화

- 발송 선점과 원장 기록을 DB 원자 연산으로 수렴해 두 탭 동시 요청의 TOCTOU와 공급자 성공·원장 실패 구간을 줄인다.
- offset 페이지네이션 중 동시 변경, 긴 poll이 느린 대화 조회를 앞지르는 경우, 대규모 ID 청크의 병렬 요청 상한을 부하 테스트로 검증한다.
- 비핵심 보조 조회가 실패해도 200으로 반환하는 경로의 부분 성공 규약과 화면 표기를 통일한다.
- 핵심 사용자 흐름 E2E와 CI, 운영 오류·지연 모니터링을 추가한다.
- 공용 계정 파일럿을 벗어날 때 사용자별 권한과 감사 추적을 설계한다.

### 4. 제품 확장

- 운영 데이터가 쌓인 뒤 `shift_request`·웨이브 발송·신뢰 점수·충족 시간(TTF) 지표를 구현한다.
- 옹매니징 정산 대조를 이행 근거로 고도화하되, 외부 TMS가 없으면 알 수 없는 운행 지표를 제품 수치처럼 단정하지 않는다.

## 문서 해석 규칙

- `PRODUCT_DIRECTION.md` §5~6의 날짜가 붙은 체크리스트와 인터뷰 결론은 **의사결정 이력**이다. 현재 미완료 목록은 이 문서가 우선한다.
- ‘코드·마이그레이션 있음’은 운영 DB 적용 완료를 뜻하지 않는다.
- 지원자의 관심·가능 응답·정보 제출은 근무 확정이나 배정이 아니다. 확정은 매니저가 한다.
