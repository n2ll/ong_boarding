# 관리자 화면의 단순화 원칙

## 제품의 기본 동선

| 목적지 | 관리자가 답할 질문 | 주요 행동 |
| --- | --- | --- |
| 오늘 할 일 | 지금 내가 처리할 것은? | 급한 대화·연락·충원·결과 확인으로 이동 |
| 모집 | 어느 라인에 누가 필요한가? | 공고 작성 → 노출 대상 확인 → 후보·필요 인원·진행 기록 |
| 지원자 대화 | 누구에게 무엇을 답해야 하나? | 대화 확인 → 답장/전화 → 처리 완료 또는 일정·결과 기록 |
| 인력풀 | 다음에 연락할 사람은 누구인가? | 조건 검색, 이력·가용성 확인, 관련 모집으로 연결 |

AI 응대 설정·외부 인력 재연락·화주사·환경설정은 공통 **관리** 메뉴에 둔다. 휴대폰에서도 접근 가능해야 한다. 기존 URL과 딥링크는 유지한다.

## 기존 디자인 시스템에서 바꿀 규칙

색상·서체·컴포넌트 라이브러리 교체보다 정보 위계가 우선이다. 색상과 간격은 `styles/theme.css`, 입력·버튼·팝오버는 기존 `components/ui`를 사용한다.

1. **탐색:** 주 메뉴는 네 개. 아이콘만 두지 않고 짧은 이름을 항상 표시한다. 휴대폰과 데스크톱의 순서를 맞춘다. 평면 메뉴에 의미 없는 상위 경로를 반복하지 않는다.
2. **행동:** 현재 단계의 주요 행동을 가장 강하게 표시한다. 미리보기·복사·직접 수정·통계는 보조 위계로 둔다. 매니저 확인이 필요한 발송·확정 절차는 유지한다.
3. **점진적 공개:** 선택 입력과 세부 조건은 제목·현재 요약을 남기고 접는다. 접기 컨트롤은 버튼/summary, 44px 이상, 키보드 포커스, 펼침 상태를 갖춘다.
4. **상태:** 미처리 건수와 오류를 숨기지 않는다. 정상 0건은 짧게 표시하고 비어 있는 카드 여러 개를 펼치지 않는다. 조회 실패를 0건/완료로 표현하지 않는다.
5. **노출 대상:** 추천 근거 → 현재 대상과 인원 → 필요 시 조건 수정. 실제 조회 실패·0명·정보 변경 경고는 상세 조건을 접어도 남는다.
6. **작업 공간:** 좁은 노트북에서 메뉴 폭을 키워 대화 영역을 압박하지 않는다. 긴 본문·대화·폼은 읽는 공간을 우선한다. 모바일은 고정 메뉴가 마지막 입력/버튼을 가리지 않는다.

## 단계별로 이어갈 범위

이번 변경은 공통 탐색·홈·공고 작성·대화 완료의 반복 마찰을 먼저 줄인다. 지원자 문자/맞춤 공고 여정과 AI 정책은 변경하지 않는다.

후보 상세와 선택 공고의 대화에서는 **연락·선탑·투입 기록** 한 버튼으로 현재 화면에서 기록한다. 기록창 상단에 공고명을 고정 표시하며, 공고별 기록과 인력풀 공통 선탑 이력은 분리한다. 저장하거나 닫으면 원래 대화와 작성 중인 문자 초안을 유지한다. Live 큐에서 이미 처리되어 사라진 후보는 저장 후 기존 다음 후보 이동을 따른다.

일반 기록창은 **메모 입력 → AI 정리 → 확인·저장**으로 시작한다. 오늘 기준일은 요약하고 다른 날짜만 펼쳐 보인다. 직접 입력과 메모만 저장도 가능하며, 직접 수정한 내용을 제외하고 메모만 저장할 때는 확인한다. 연락·선탑·결과를 지정한 업무 링크는 해당 입력 화면으로 바로 열린다.
