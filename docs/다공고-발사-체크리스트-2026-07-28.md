# 다공고 동시 게시 발사 체크리스트 (2026-07-28)

> 공고 6~7개를 한 번에 올려 **내부 인력풀('우리 인력에게')** 로 구인하는 첫 운영. 이 문서는 매니저가 그대로 따라 하는 순서다.
> 근거: 5갈래 코드 감사(등록·지원자화면·발송·AI응대·관제) + 프로덕션 데이터 실측. 코드로 막은 것은 `[코드]`, 사람이 지켜야 하는 것은 `[사람]`.

## 1. 공고 하나를 만들 때 반드시 채우는 값 `[사람]`

7개 전부 아래를 채운다. **비우면 AI가 그 질문마다 매니저에게 넘긴다**(7개면 인계 큐가 7배가 된다).

- [ ] **제목** — 7개가 서로 다르게. 권역·요일·시간대를 넣는다(예: `강남·신사권 오전`). 목록에서 공고를 구별하는 축은 사실상 제목뿐이다.
- [ ] **화주사** — 고른다. 비우면 목록의 화주사 필터에서 그 공고가 사라진다.
- [ ] **모집 인원** — 실제 티오를 타이핑한다. **기본값 1이 가장 위험**하다: 1명 확정되는 순간부터 나머지 관심자에게 "자리가 모두 차 있어요"가 나간다.
- [ ] **마감시각** — 넣는다. 비우면 영구 게시 + 마감 안내 모드가 작동하지 않는다. 정기 라인이라 일부러 비울 때는 **모집 기간을 '정기'로** 반드시 선택.
- [ ] **시작일** — 오늘 이후. (`[코드]` 지난 날짜는 등록이 차단되고, 복제할 때는 비워진 상태로 들어온다.)
- [ ] **급여** — 단가 형태 + 금액 + 정산 문장. **라인마다 다르면 복제로 따라온 값을 반드시 지우고 새로 쓴다.**
- [ ] **집결지 · 마지막 경유지** — 주소를 넣고 저장 후 좌표가 잡혔는지 확인. 비우면 거리 정렬·거리 표시·만남장소 문안이 전부 죽는다.
- [ ] **근무시간** — '우리 인력에게'는 자유 텍스트다. 비우면 지원자 화면에서 근무시간 줄이 사라지고 시간 문의가 전부 인계로 온다.
- [ ] **AI 응대 근거** — `근무 상세 · AI 응대 근거` 접이식을 **열어서** 확인한다(기본 접혀 있다). 라인마다 다른 단가만 각 공고에 넣고, 7개 공통 정책(정산일·유류비·선탑·법인차)은 **에이전트 두뇌 탭 지식에 한 번만** 넣는다.
- [ ] **모집 방식 = 우리 인력에게** (기본값). '새로 모집'이면 맞춤 공고 링크에 안 뜬다.
- [ ] **노출 대상 = 전체 노출**. 지정 노출을 쓸 거면 조건을 최소 1개 넣는다(비우면 아무에게도 안 보이는 공고가 등록된다).
- [ ] 초안 영역에 **`오프라인 템플릿` 회색 배지**가 보이면 제목·본문을 손본다(AI 실패 폴백이라 제목이 `[] 배송 모집`으로 나갈 수 있다).

## 2. 7개를 만드는 순서 `[사람]`

1. **1번 공고는 AI 초안으로 등록**(초안 없이는 등록 버튼이 잠긴다).
2. 2~7번은 목록 행의 `⋯` → **`이 공고 복제해서 새로 등록`**.
3. **복제 직후 반드시 덮어쓸 5개**: 제목 / 마감시각(복제되지 않음) / 시작일(비워져 있음) / 모집 인원 / 급여·AI 응대 근거.
   - 복제는 급여·집결지·정책·참고정보를 **그대로 가져온다.** 옆 라인 값이 남으면 AI가 그 값으로 **확답**한다(문자는 되돌릴 수 없다).
4. **하루에 7개를 몰아 올리지 않는다** — 2~3개씩 나누면 한 사람 링크에 뜨는 카드 수가 줄어 오클릭·선점 문제가 완화된다.
5. **마감 정리와 신규 게시는 하루 이상 띄운다** — 같은 날 하면 24시간 교차 가드로 "5명 발송 예정 → 0명 발송"이 된다(정상 동작, 실패 아님).
6. 등록 직후 뜨는 **'대기자에게 안내' 모달은 7개 중 1개에서만 발송**, 나머지는 건너뛰기. 문자의 맞춤 공고 링크가 7개를 다 보여주므로 1통으로 충분하다.

## 3. 발송 순서 `[사람]`

1. 먼저 **공고탭 '대기자에게 안내'** 로 약속자에게 1통(현재 대상 5명).
2. 그다음 **파이프라인 '문자 보내기'로 인력풀 고지 단 1통** — 자유 본문 + `#{맞춤링크}`. **공고를 하나씩 7번 보내지 않는다.**
   - `[코드]` 목적을 안 실은 캠페인도 24시간 교차 가드를 타므로, 실수로 두 번 눌러도 같은 사람에게 두 통이 가지 않는다.
3. 1번에서 보낸 5명은 대상에서 뺀다(같은 날 두 경로가 겹치면 2통).
4. `발송 준비 > 최근 14일 안에 캠페인 문자 보낸 분 제외`를 켠다(기본 꺼져 있다).
5. **이미 확정된 54명**: 운행이 멈춰 대기 중인 분이면 보내도 된다. 지금 근무 중인 분이면 진행 단계에서 `확정인력`을 빼고 보낸다. `[코드]` 모달이 포함 인원 수를 알려준다.
6. 차량이 필요한 라인을 알릴 때는 **차량 조건**을 확인한다(도보·미확인이 기본 포함이고 서버가 막지 않는다).
7. 발송을 시작하면 **탭을 닫지 않는다**(565명이면 20분 안팎). 실패 토스트가 떠도 **10분 안에 재시도하지 않는다**(이미 나간 사람에게 중복 발송).

## 4. 매일 관제 순서 `[사람]`

1. **관심 표시 큐** — 공고별로 훑는다. **여기가 핵심**: 한 사람이 여러 공고에 관심을 눌러도 자동 응대는 **첫 1건만** 나간다. 나머지는 문자가 안 나갔으니 수동으로 연락한다.
2. **Slack 알림** — `자동 편입을 건너뜀`·`같은 분의 추가 관심 N건은 큐에 남겨뒀어요` 줄이 보이면 그 사람은 수동 처리 대상이다. `[코드]` 이 알림은 이번에 추가했다(예전엔 전건 스킵이면 알림이 아예 없었다).
3. **사람 확인 필요(paused) 큐** — 한 사람이 여러 카드로 뜰 수 있다. 카드에 공고명이 없어 열어서 확인한다.
4. **확정 대기 큐** → 확정.
5. **충원율 게이지** — `[코드]` 이제 '그 공고에 확정된 사람'만 센다. 그래도 `충원 완료 — 마감하기`를 누르기 전에 실제 확정 인원을 한 번 확인한다(마감하면 미선발 관심자에게 안내 문자가 나간다).

## 5. 절대 하지 않는 것 `[사람]` — 코드가 막지 않는다

- [ ] **확정은 지원자 상세의 확정 모달로만.** 파이프라인 일괄 상태 변경으로 '확정인력'을 만들지 않는다 — 다른 라인 집결지·시작일로 만남장소 문자가 조립되고, 확정된 사람에게 AI가 계속 스크리닝 질문을 보낸다.
- [ ] **만남장소·첫날 안내를 보내기 전 미리보기의 일시·집결지·라인 종류를 눈으로 읽는다**(도시락 라인에 비마트 배차 문구가 나갈 수 있다).
- [ ] **매니저 답장은 실시간 응대에서 공고를 선택한 상태로** 한다.
- [ ] **'지원자 화면' 미리보기에서 관심 버튼을 누르지 않는다**(테스트 계정이 후보로 붙는다).
- [ ] **수동 마감(상태만 마감)보다 마감시각 경과를 쓴다** — 수동 마감은 지원자 링크에서 카드를 즉시 사라지게 해 접수 흔적이 없어진다.

## 6. 발사 직전 전역 확인 `[사람]`

- [ ] **AI 모드** — 지금 `자동`이다. **첫날은 `코파일럿(초안만)`으로 두고** 반응량을 본 뒤 자동으로 올린다. 자동이면 관심 클릭마다 즉시 실문자가 나간다.
- [ ] **에이전트 두뇌 지식이 7개 라인 전부에 사실인지** 확인(익월 5일 지급·과태료 회사 부담 같은 단정 문구가 전 라인 공통으로 주입된다). 다른 라인은 그 공고의 'AI 응대 근거'로 덮는다.
- [ ] 연락처 없는 확정인력 1명(안현진) 연락처 확인.
- [ ] 전화번호 중복 2쌍 정리(같은 사람이 두 행으로 있으면 관심·확정 이력이 갈린다).

## 남는 위험 (사람이 메꿔야 함)

1. **한 사람이 여러 공고에 관심을 눌러도 첫 건만 자동 응대된다.** 화면은 7장 모두 "접수됐어요"라고 하므로, 관심 큐에서 미발송 건을 매일 직접 처리해야 한다.
2. **어느 공고 얘기인지 AI가 틀릴 수 있다.** 인입 문자를 '직전에 보낸 문자의 공고'로 앵커링하고, 캠페인 문자에는 그 값이 없다. 답장은 미답 큐에서 사람이 확인한다.
3. **복제 후 급여·AI 응대 근거 덮어쓰기를 한 번 빠뜨리면** 옆 라인 단가가 확답으로 발송된다(되돌릴 수 없다). 코드가 막지 않는다.
