# multi-job consultation spec
design:
  - 기존 단계의 Claude 호출 한 번에서 현재 공고 진행 / 복수 공고 상담 / 대상 확인을 구조화해 구분한다.
  - 상담 가능 공고는 현재 지원자의 노출 정책과 기존 외부 공고 연결을 확인한다. 조회 실패는 자동 답변을 중지한다.
  - 모델은 공고별 안내 항목과 발언 원문을 지정한다. 응답의 조건 값은 서버가 공고 데이터에서 직접 구성한다.
  - 상담 턴은 기존 체크리스트·프로필·대화 초점을 변경하지 않는다. 명확한 현재 공고 진행만 기존 단계를 사용한다.
  - 답변에 없는 조건·배정 가능 여부는 추측하지 않고 관리자 확인으로 넘긴다.
  - 최근 대화와 연속 수신 문자를 함께 읽되, 새 관찰 기록은 이번 미응답 수신 문자에 있는 인용문만 허용한다.
  - 조회된 공고가 하나로 줄어도 직전 복수 상담의 모호함을 유지한다. 진행 후보가 없는 경우는 기존 진입·관리자 흐름을 사용한다.
data:
  - pool_events에 job_consultation_observation을 기록한다. 공고·수신문자별 멱등 키, 원문·종류·출처를 보존한다.
  - 자동 모드에서만 관찰 이벤트를 저장한다. 코파일럿은 초안 reasoning에 검토할 발언을 표시하고 실제 접수 완료를 약속하지 않는다.
  - 복수 공고 응답은 한 공고의 확정된 대화 앵커로 취급하지 않는다.
  - 자동 상담의 수신·응답 문자 job_id는 null, 공고별 responded_at·전역 상태는 변경하지 않는다. 관찰 이벤트의 job_id로 발언만 구분한다.
failure:
  - 알 수 없는 공고/항목/원문, 불완전한 모델 출력 -> 발송·의사 기록·단계 진행 중단, 관리자 확인.
  - 기록 실패 -> 저장됐다는 문자를 보내지 않는다.
  - 최근 50개 조회에서 미응답 구간의 시작을 확인하지 못하면 일부 원문만 해석하지 않고 관리자 확인으로 넘긴다.
  - 기존 지원자 단위 reply claim과 수신거부·AI off·불명확 발송 보호를 유지한다.
rollback: AI off 후 이전 앱으로 복구. 관찰 이벤트는 감사 이력으로 보존한다. PR129의 선행 DB 마이그레이션 순서를 유지한다.
acceptance: A/B 조건 질문, 둘 다 비교, 공고별 가능 시간, 불명확 긍정, 관심만 표시한 공고, 비노출 공고, 연속 문자, draft/off, 중복 실행, 기존 단일 공고 진행을 실발송 없이 검증한다.
