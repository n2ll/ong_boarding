# Spec
- 상담 노출을 통과한 현재 지원자의 유효 후보 연결에만 `staffing_preparation` 최신 전체 스냅샷을 붙인다. created_at DESC, id DESC 후 검증한다. 과거 값으로 보충하지 않는다.
- 전달값은 선탑 상태/백업 의사, 선탑 가능 날짜·시간 존재 여부, 실제 선탑/백업 이력 유무, 후속 연락 할 일/연락 기록 유무뿐이다. 메모/담당자/상세 장소/연락 결과/자유문장/일정 원문은 전달하지 않는다.
- 조율/예정/완료/보류, 실제 선탑·백업 이력, 백업 거절, 날짜·시간 모두 확인된 공고에는 신규 선탑 질문을 붙이지 않는다. 부분 확인은 미확인 부분만 묻는다. A 기록으로 B 질문을 생략하지 않는다.
- 일반 라인의 현재 공고에 선탑 진행 근거가 있으면 단일 공고도 기존 `processConsultation` 전용 처리기를 사용한다. 스크리닝 지침·체크리스트와 상담 지침의 충돌을 제거하고 한 번의 Haiku 호출로 서버가 답변을 구성한다. 이 단계에서는 체크리스트 자동 전진 대신 공개 조건 답변과 신규 원문 관찰을 유지한다. 연락 기록만으로 선탑 진행/배정을 추정하지 않는다.
- 관리 기록은 신규 지원자 발언이 아니며 관찰 원문으로 복사하거나 기존 정보를 자동 변경하지 않는다. 개인 일정·배정 변경 요청은 기존 매니저 인계 경로를 유지한다.

## Failure / rollback
조회 오류나 최신 기록 손상은 기존 상담 자료 실패 경로로 넘겨 자동 발송을 막는다. 운영 데이터/AI 설정/SMS 변경은 없다. 이상 시 본 PR을 revert하여 이전 문맥 구성으로 복구한다(DB 변경 없음).

## Acceptance
최신/삭제/범위/개인정보/오류 조회 테스트, 다중 공고 재질문 억제, 단일 일반 라인 상담 전환, 실제 stage 경로 상태 불변 검증. Haiku 소수 가상 사례로 문의 답변/인계 분류를 확인한다. UI 변경이 없어 브라우저 E2E는 추가하지 않는다.
