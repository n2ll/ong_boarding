# Containment spec
- `agent_kill_switch`: `draft`만 전역 초안 허용. `0`, 빈값, 미설정, 손상값은 OFF.
- 검수 JSON에 `job_ids` 필수(중복 없는 양의 정수 1~3개). 기존 공고 없는 검수 JSON도 OFF.
- API: 전체 auto/disabled:false 요청 거절. 검수 시작 시 테스트 계정과 활성 실공고 확인. 개별 paused 상태는 변경하지 않는다.
- 응답 시작/모델 후/발송 직전에 대상·공고·수신 시각을 검증. 복수 공고 자료와 미응답 원문도 전부 범위 안이어야 한다. 범위 밖은 매니저가 수동 응대한다.
- 예약 리마인더, 자동 최초 컨택, 미등록자 자동 편입은 검수에서 실행하지 않는다. 직접 제출한 지원서의 단순 접수증은 유지하되 대화를 시작하는 문구는 사용하지 않는다.
- 실패: 저장 상태 조회 실패/종료/범위 불일치 시 새 발송과 단계 진행 없음. 이미 공급자 접수된 발송의 기록 복구는 별도 계약 유지.
- rollback: 운영 OFF 유지 후 코드만 되돌린다. 자동 모드·수동 중지를 복원하지 않는다.
- 배포 한계: 새 코드는 구버전 배포의 키를 회수하지 못한다. Vercel 접근 통제/운영 키 분리 확인은 별도 필수 게이트.
