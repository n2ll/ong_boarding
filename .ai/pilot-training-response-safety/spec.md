# Spec
- 명확한 대화 종료에는 질문/꼬리인사/단계전환 추가 발송을 하지 않는다. 단순 감사의 종료 맥락과 대기 중 질문에 대한 긍정을 구분하고, 원문에 실질 질문/가용성/수신거부가 함께 있으면 누락하지 않는다.
- 수신거부는 기존 저장·차단 계약을 유지한다. 대화 종료만으로 영구 수신거부 또는 근무 거절을 만들지 않는다. 이후 새 실질 질문은 다시 응대한다.
- 선탑·정산 안내는 현재 공고 정보를 사용한다. 교육 라인이 실제 백업할 라인과 다를 수 있음을 설명하고, 교육≠배차 확정. 시간/장소/미투입 교육비 조건은 근거 없이 만들지 않는다.
- 준비표 제안은 source message/quote/job/received_at 근거를 함께 표시하며, 명확한 날짜에만 해석한다. 기존 관리자 저장값 및 본담당/예비 선택을 자동 덮어쓰지 않는다.
- 다른 공고 같은 날짜 본담당 후보 중복은 확인 경고다. 실제 확정/배정 쓰기는 없다.
- 모든 외부 발송 보호는 기존 pilot/scope/claim/미응답/확정표현 검증을 통과한다. 발송/DB 불명 상태에서 자동 재발송하지 않는다.
- 운영 공고 변경은 이전값 비공개 백업·updated_at CAS·재조회로 검증한다. 코드는 revert, 데이터는 변경 전 값으로 복구 가능하다. 발송은 되돌릴 수 없어 이번 검수는 외부 호출 없는 회귀/브라우저 위주다.

## 실제 응대에서 추가 확인한 필수 수정
- 교육 일정·시간 질문에 배송 근무시간을 안내한 사례가 있음. 상담 필드 `선탑·교육`을 분리하고 `ai_facts`의 같은 이름으로 명시된 한 줄만 인용한다. 교육 질문을 배송 조건으로 대체하는 응답은 발송 보류한다.
- auto_sent 판단 이력 INSERT가 필수 applicant_phone을 누락함. 필드를 포함하고 오류를 기록하되 이미 발송·저장된 문자는 재전송하지 않는다. 과거 누락된 reasoning은 추측 복원하지 않는다.
- 순수 종료는 모델 호출 없이 처리 시각만 기록한다. 날짜·거절 등이 섞인 종료는 기존 검증을 거쳐 정보는 보존하고 추가 답장·advance 발송을 막는다.
