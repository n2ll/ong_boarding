# 검증 기록

## 통과
- `npm run build` 성공(TypeScript 포함). 기존 테스트 파일의 `module` 변수 ESLint 경고 3건만 남음.
- 메뉴·딥링크·이탈 보호·홈 업무 상태·공고 검증·노출 대상·응대 완료 관련 Node 테스트 78/78.
- 긴급 기록/비용 조회의 빈 응답·잘못된 형식·조회 실패 구분 테스트 8/8.
- 변경 파일 ESLint 및 `git diff --check`.
- 합성 데이터로 실제 컴포넌트를 렌더해 로컬 브라우저 검수. 정상/0건/조회 실패를 사용했으며 운영 DB·문자·AI API 호출 없음.
- 데스크톱 1280px: 네 메뉴 이름, 간결한 홈, 보조 관리 메뉴, Escape 포커스 복귀.
- 모바일 390px: 하단 다섯 메뉴, 관리 목적지 접근, 홈 조회 실패 경고, 공고 시작 화면과 모달 하단 버튼.
- 공고 초기 입력은 메모와 선택 조건만 표시. 직접 작성 시 위치·인원·급여 확인 영역 자동 표시.
- 노출 상세가 접혀 있어도 0명 경고와 현재 인원 표시. 추천 적용 후 상세 조건을 열면 추천값이 반영됨.

## 리뷰에서 보완
- 관리 팝오버를 열면 로그아웃 대신 첫 관리 링크에 키보드 포커스를 둔다.
- 홈의 긴급 기록은 HTTP 성공뿐 아니라 응답 형식까지 기존 `sosLedgerCardView`로 확인한다. 조회 불명/오류/오래된 응답이면 접지 않는다.
- 예전 3열 카드 CSS를 강제하던 두 테스트는 새 목록 설계와 상충해 제거했다. 업무 상태·우선순위·재시도 검증은 유지한다.
- 공고 E2E 시나리오의 선택 조건/노출 상세 펼침 단계를 새 흐름에 맞췄다.

## 범위와 한계
- 실제 발송·지원자 정보 수정·확정·AI 응대 모델/정책 변경 없음.
- 자동 Playwright E2E 전체를 실행하지 않았다. 영향 화면은 로컬 합성 데이터로 직접 조작하고 확인했다.
- 로컬 검수용 임시 라우트는 제거했다.
- 지원자 상세에서 여러 공고의 선탑·투입 기록을 합치는 작업은 포함하지 않는다.
