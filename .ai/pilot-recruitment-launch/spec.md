# Spec
- 승인된 중단 답장 1건의 최신 상태와 미응답 여부, 수신 거부, 공고와 파일럿 범위·만료를 재확인 후 재개한다. 다른 paused 대상은 변경하지 않는다.
- 실제 응대는 현행 Haiku 모델과 기존 router/sender/lock/출처·확정 표현 검증을 통과해야 한다. 중복 응답 또는 전역 활성화 금지.
- 공고 본문·정책·대금 안내·AI 참고정보의 교육비를 같은 예상 표현으로 갱신한다. 최신값 조건부 갱신과 비공개 이전값 백업을 남긴다.
- UI의 연락 근거는 실제 동의 필드를 덮어쓰지 않는 기존 한시·대상·목적 제한 이벤트를 사용한다. 수신 거부는 항상 제외한다.
- 모든 실제 발송 및 제한 응대 변경은 관리자의 명시적 검토·클릭 뒤에만 실행한다. 발송 성공자만 후보 연결하고 실패·결과 불명은 구분한다.
- 부분 실패와 네트워크 오류에서 결과를 숨기거나 자동 재발송하지 않는다. 기존 실행 중 파일럿을 조용히 교체하지 않는다.
- 실패 시 해당 건의 기존 중지/수동 검토 상태를 보존 또는 복구한다. 코드 롤백은 revert, 공고 수정은 저장한 이전값 기준 복구이며 발송 자체는 되돌릴 수 없다.

- `resume`의 `reply_to_latest` 옵션은 관리자 인증 경로에서 원본 ID/원문/수신시각을 재사용한다. 재개 전 및 대화 잠금 안에서 최신·미응답을 재확인하고, 수동/인력풀 발송 원장의 처리 중·불명 건도 차단한다. 단계와 updated_at CAS로 동시 재개를 막는다.
- 기존 이후 응대 재개는 재처리를 하지 않는다. 대기 답장은 실제 답장 또는 단계 전환 안내 발송 시에만 성공으로 표시한다. 결과 불명 시 잠금을 유지하고 재시도하지 않는다.
