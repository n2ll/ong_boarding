# 검증
- 운영 화면 읽기 전용: 인계 3건 중 2건은 관리자 직접 응대 중지, 1건은 SOLAPI 길이 제한 실패였다. 자동 응대 재개·처리 완료·문자 발송·DB 변경 없음. 실제 실패 본문은 확인하지 못했다.
- `npm run test:core`: 383/383 통과, 실패/스킵 없음. 인메모리 fixture와 네트워크 차단을 사용해 외부 모델·문자·운영 DB 호출 없음.
- 길이 사전 차단/구형 오류 분류/긴 동일 조건 중복 회귀는 수정 전 실패를 확인하고 수정 후 통과. 서로 다른 조건을 요약하거나 제거하지 않는다.
- `npm run build`: 통과. 초회 버튼 variant 타입 오류를 수정 후 재실행. 기존 테스트의 `no-assign-module-variable` 경고 3개는 남아 있다.
- 로컬 브라우저: 실제 `JobPostingBodyEditor`를 임시 페이지에서 가상 데이터로 실행. 빠진 조건 4개 표시 → 보완 버튼 입력 포커스 → 조건 입력 후 질문 제거와 원문 반영 확인. 전체 편집 포커스, 390px 너비 줄바꿈/버튼 배치, SMS에서 질문 제외 확인. 임시 페이지·서버·탭 제거. 실제 공고 저장이나 실문자 검수는 수행하지 않음.
- 독립 변경 리뷰: 발송 결과 불명 시 재발송 방지 유지, 원문 동일 블록만 묶기, 기존 모호한 대상·사실 검증 유지 확인.
- CI: PR/main에서 Node 22 + npm ci + test:core + build. secrets 없이 가짜 public Supabase 설정만 사용. 최소 contents read, 중복 실행 취소. 실제 Actions 결과는 PR에서 확인한다.

# 남는 한계
- 다른 조건이 많거나 후속 문구를 더한 답변이 여전히 길면 발송 전에 중지하고 관리자로 인계한다. 무조건 자동 답변하거나 여러 문자로 분할하지 않는다.
- 운행 조건 질문은 본문 패턴 기반 보조 안내다. 복잡한 자유문장에서는 추가 확인이 필요할 수 있고, 질문이 없다는 것만으로 조건 완비를 보증하지 않는다.
- 이번 변경은 일반적인 AI 질문 해석 범위나 지원자 장기 기억을 확장하지 않는다.
- 바이트 기준 근거: https://solapi.com/developers/api/messages-lms (한글 2byte, LMS 최대 2,000byte).
