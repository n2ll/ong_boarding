# 명세
- 확인한 원인: 운영 인계 목록에 SOLAPI 문자 길이 초과 실패가 정책 문의로 표시되어 있었다. 실패한 실제 발송 본문은 확보하지 못했으므로 중복 안내가 그 건의 원인이라고 단정하지 않는다.
- AI: 여러 공고 상담 답변이 길이 제한을 넘을 때, 공고별 안내 블록 전체가 동일한 경우에만 공고명을 함께 표시하고 원문을 한 번 안내한다. 다른 조건을 합치거나 요약·절삭하지 않는다. 모델 호출과 응대 범위는 추가하지 않는다.
- 문자: 공통 발송 함수에서 한글 2/ASCII 1 기준 2,000byte 초과를 발송 전에 차단한다. 비BMP 문자는 보수적으로 4byte 계산하며 문자 인코딩 지원 여부 검증을 대신하지 않는다. 초과하거나 공급자/기록 실패 시 `delivery` 사유와 다음 행동으로 인계한다. 전송 결과 불명은 재발송하지 않는다.
- 인계 UI: 과거 발송 실패 문구도 문자 발송으로 분류해 공고 정책 보완으로 잘못 유도하지 않는다. 기존 관리자 직접 응대 중지는 유지한다.
- 공고: 기존 원문→초안 흐름에서 수거가 있는 경우 수거 방식/대상 가방, 반납이 있는 경우 장소/기한의 빠진 조건을 알려주고 관리자가 보완한다. 없는 조건은 추정하지 않고 명시적 수거 없음은 질문하지 않는다.
- CI: 기존 결정론적 핵심 검사와 build(타입/lint)를 인증정보/운영 DB/외부 모델 없이 실행한다. 취소 가능한 PR 작업, 최소 read 권한.
실패: 모델/조회/검증 실패시 안전한 인계 유지, 공고 미정 항목은 임의 저장하지 않음. 중복 제거 후에도 길면 문자를 나눠 보내거나 내용을 버리지 않고 인계한다.
롤백: 이 PR revert. 스키마 변경 없음, 발송 정책 재활성화 없음.
검증: 변경 행동에 대한 최소 실패→통과 회귀, 통합 핵심 검사, build, 공고 생성 UI 모의 브라우저 확인.
