# 검증

- `npm run build` 성공(TypeScript 포함). 기존 테스트 파일 ESLint 경고 3건. 최초 빌드에서 nullable 공고명 전달을 발견해 기존 상세와 같은 빈 문자열 기본값으로 수정 후 재빌드했다.

- 기존 기록·충돌·AI 메모 제안·선탑·참여 관련 테스트 64/64, 이탈/공고 진입 테스트 24/24 통과(공고 진입 3건 중복).
- 변경 3파일 ESLint 및 diff check 통과.
- 합성 데이터로 실제 ApplicantDetailPanel/StaffingPreparationPanel을 로컬 브라우저에서 확인. 모든 API를 로컬 대체하고 알 수 없는 API는 차단했다.
- 성동/강남 두 공고를 각각 열면 해당 공고의 기존 기록만 로드. 공고 미지정 대화에는 임의 기록 버튼이 없다.
- 대화와 상세 양쪽에서 기록 진입. 편집 시 상위 미저장 보호 활성, 닫기 취소 시 초안 유지, 버린 뒤 보호 해제.
- 저장 후 같은 URL·현재 대화·공고 유지, 버튼 포커스 복귀. 작성 중인 문자 초안도 기록창 개폐 후 유지.
- 조회 실패/후보 누락 시 오류와 닫기·재조회만 표시하며 빈 폼/저장 버튼을 열지 않는다.
- 390px 모바일에서 선탑 폼과 고정 저장 버튼 확인.
- 읽기 리뷰: 현재 후보가 Live 큐에서 제거된 경우 저장/닫기 후 다음 후보 자동 이동은 기존 정책을 유지하며 spec에 예외 명시.
- 개인정보, 운영 DB, 문자 발송, AI 호출 없음. 임시 로컬 검수 라우트 제거.
