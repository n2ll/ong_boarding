# 동작 명세
flow:
  - 다른 지역 문의 → 현재 노출 범위의 근거 안내 또는 적합 공고 확인 어려움 → 원문 기반 희망 권역 저장 → 이후 권역 일치 공고 안내 우선 검토.
  - 백업 관심·가능일 → 등록된 선탑 조건 안내 + 참여 의사/본인 가능시간 질문 → 관리자 준비표에서 원문·다음 확인 확인 → 대화/전화 → 일정·접선 정보·메모 기록.
boundaries:
  - 권역 일치는 우선 연락 검토 근거이며 출퇴근 적합·지원 의사·근무 확정이 아니다. 불명확한 인접성/소요시간 추측 금지.
  - 알려진 조건 밖의 협상·배정·정확한 주소는 기존 관리자 확인 유지. 자유로운 모델 답변을 무검증 전송하지 않는다.
data:
  - 기존 pool_events에 region_preference 원장(원문, 수신 id/시각, 지역 목록, job_id null). 기존 전체 인력풀 선호·동의값 덮어쓰기 없음.
  - 기존 선탑 진행/팀 메모 API 재사용. 새 스키마 없음.
failure:
  - 원문 불일치/기록 실패 → 안내 완료·저장 성공을 주장하지 않고 검토로 보낸다.
  - 지역 이력 조회 실패 → 부분 추천을 성공으로 반환하지 않는다.
  - 기존 중지·종료·배정/발송 제한 그대로 적용. 자동 재처리 없음.
verification:
  - 지역 답변/부정·혼합 질문/원문 검증, 영속 기록 중복/실패, 새 공고 권역 우선순위 및 노출·수신 제한 회귀.
  - 관심 이후 선탑 후속 질문·반복 억제, PC/390px 대화 연결 및 기록 유지 fixture 검수.
  - 최종 타입·빌드·diff 확인. 실제 지원자에게 검수 문자 발송 없음.
rollback: 이 변경 커밋 revert. region_preference 원장은 보존하되 이전 버전은 사용하지 않음. 운영 응대 범위·기존 상태 변경 없음.
