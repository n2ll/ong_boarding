# multi-job conversation focus
goal: 여러 공고에 관심을 가진 지원자가 한 SMS 대화에서 현재 공고를 명확히 알고 안전하게 전환한다.
trigger: 다른 공고 응대 중 두 번째 공고에 관심을 표시하면 관심은 저장되지만 새 공고 안내가 조용히 생략된다.
users: [지원자, 매니저]
must:
  - 여러 공고 관심과 후보 상태를 동시에 유지한다.
  - SMS 자동 응대는 지원자별 현재 공고 한 건만 기본 문맥으로 사용한다.
  - 개인 공고함에서 관심만 저장하거나 새 공고로 문자 대화를 명시적으로 전환할 수 있다.
  - 전환 뒤 공고명이 없는 일반 답장은 새 현재 공고로 귀속한다.
  - 모호하거나 충돌하는 답장은 추측하지 않고 되묻거나 매니저에게 넘긴다.
must_not:
  - 관심·전환을 근무 확정이나 배정으로 표현하지 않는다.
  - 관리자 확정 인력의 공고 결속을 지원자 동작으로 바꾸지 않는다.
  - 대량·캠페인 문자를 대화 초점 근거로 사용하지 않는다.
decisions:
  - applicants.conversation_focus_job_id로 명시적 대화 선택을 관리한다. 미확정자의 기존 current_job_id는 발송 호환성을 위해 함께 변경하되 관리자 확정 결속은 보호한다.
  - SMS 번호 하나에서 여러 공고를 병렬 스레드로 운영하지 않고 현재 공고 한 건을 명시적으로 전환한다.
  - 전환은 개인 공고함의 구체적인 공고 버튼으로만 수행하고 자유문장만으로 자동 전환하지 않는다.
success:
  - A 공고 대화 중 B 공고 관심 표시에서 관심만 저장과 문자 대화 전환을 구분해 제공한다.
  - B로 전환한 뒤 공고명이 없는 답장이 B 후보로 라우팅된다.
  - 전환 실패·재시도·야간 처리에서 중복 SMS나 잘못된 공고 응답이 발생하지 않는다.
  - 확정 인력과 수신거부 지원자는 전환할 수 없다.
