# 동작 명세

- handoffs GET의 기존 handoffs/total/by_category는 처리 필요만 반환한다. held/held_total은 별도 보관 목록이다. DB 상태는 수정하지 않는다.
- 공통 분류 함수로 handoffs와 notifications를 집계한다. 정확한 수동 중지·검수 종료 시스템 문구와 명시적 검수용 공고 표지만 보관한다. 일반 제목의 '테스트'나 카테고리 manual/auto만으로 제외하지 않는다.
- 처리 완료 시각이 현재 중지 이후임을 확인한다. 과거 완료 기록이나 불명확한 사유는 처리 필요로 남긴다. 중지 시각이 없는 구데이터는 유효한 완료 시각을 인정한다(기존 완료 API가 중지 시각을 보충하지 않음).
- UI: 처리 필요 / 중지·검수 보관 전환, 처리 필요 사람 수는 사유 필터·보관 열람과 무관하게 고정한다. 보관에는 방치 표시·전화·재개·처리 완료 액션이 없다.
- 실제 인계는 사유 → 권장 조치 → 대화 확인/공고 반영. 기존 재개·완료 액션은 명시적인 추가 옵션으로 열고, 즉시 문자 발송 여부를 설명한다.
- 제한: 기존 구데이터 검수 구분은 명시적 제목 표지에 의존한다. 불명확한 건은 숨기지 않는다. 자동 재처리나 운영 대응 능력 자체를 변경하는 작업은 아니다.
