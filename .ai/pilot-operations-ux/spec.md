# Spec
- 후보 수는 연결 관계, 관심 수는 검증된 interest_click 집계. NULL stage는 시작 전이며 관심으로 추정하지 않는다.
- 공고별 배차 준비를 pool_events의 append-only staffing_preparation 이벤트에 기록한다. 관리자 기록만 저장하며 날짜별 availability/후보역할, 선탑 가능시간, 메모를 포함한다.
- 실제 날짜·중복·길이·후보 소속 검증. 가능한 날에만 본담당/예비 후보를 지정한다. 저장은 확정·문자·AI 단계 변경을 유발하지 않는다.
- 최신 이벤트가 잘못되면 확인 필요. 조회 실패를 빈 기록으로 취급하지 않는다. 네트워크 재시도는 동일 UUID를 유지하고 내용 변경 시 새 UUID를 쓴다.
- 동시 편집은 마지막 저장 기준이며 모든 이력을 남긴다. 확정 배차 및 날짜별 목표 인원 자동 판단은 범위 밖이다.
- 기존 DB 테이블을 재사용하므로 마이그레이션 없음. 문제 시 UI/API 변경을 되돌려도 기록은 보존된다.
- 대량 안내는 답변 완료 경계나 현재 공고 선택 근거로 사용하지 않는다. 최신 안내의 번호·제목을 현재 허용 공고에 유일하게 매핑한 참조만 상담 문맥에 추가한다.
- 번호 매핑이 없으면 재확인한다. 의사 기록은 각 수신 원문에서 선택한 공고와 대조하며, 정확한 원문 인용 검증은 완화하지 않는다. 실패 시 기존 관리자 인계를 유지한다.
- 이미 중지된 지원자를 다시 활성화하지 않는다. 변경의 롤백은 코드 revert이며 기존 전역 OFF/제한 대상/만료 시각을 수정하지 않는다.
