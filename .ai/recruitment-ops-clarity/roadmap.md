# 관리자 업무 중심 개발 순서 — 2026-09-10
제품의 성공은 문자 수·AI 비율보다 필요한 날짜에 실제 투입 가능한 배송원을 확보하는 것이다. 아래는 다음 개발 순서이며, 이번 변경으로 구현 완료했다고 간주하지 않는다.

| 순서 | 필요한 변화 | 화면·AI 역할 | 완료 기준 |
|---|---|---|---|
| 1 필수 | 라인×날짜 충원판 | 9/21·22·23별 필요/확정/예비/부족 표시. AI가 관심·가능일 원문을 정리하고 관리자가 확정 | 같은 사람이 같은 시간 여러 라인에 중복 확정되는 것을 경고. 관심은 충원으로 계산하지 않음 |
| 2 필수 | 선탑 연락부터 실제 투입까지 이어지는 기록 | 관심자 카드에 관심 근거, 가능한 선탑 날짜·시간, 마지막 연락, 담당자·다음 행동. 통화/문자 후 같은 곳에서 결과·팀 메모 저장 | 선탑 확정/참여/백업 가능/실제 투입 구별. 이미 답한 질문을 다시 묻지 않음. 기존 참여 이력 재사용 |
| 3 필수 | 답할 수 있는 문의 자동 해결률 개선 | 실패 이유를 개인정보 최소 형태로 남기고 가상 회귀로 원인 재현. 공고에 답이 있으면 응대, 일정 충돌·조건 미정만 사람에게 | 공고별 근거·한 번의 답변·마무리 의사 존중. 추가 문의를 임의 종결하거나 불확실한 사실 생성하지 않음 |
| 4 다음 | 배송·수거·반납 타임라인과 원문→공고 초안 | 원문 붙여넣기→상차/배송/맞수거/재방문/반납 요약→미정 항목만 질문. 작성자는 근거와 수정사항을 확인 | 맞수거/오후 재방문·가방 날짜·반납 완료시간을 개별 구분. 비슷한 화주사라도 다른 공고 조건 복사 금지 |
| 5 이후 | 예비 인력 재활용과 충원 제안 | 실제 참여, 지역·차량·가용성에 근거한 추천 이유/확인할 조건 표시. 관리자 대상 수정·발송 검토 | 나이로 배제하지 않음. 비마트 제외 등 운영 범위와 수신 중지 존중. 실제 이력 없는 숙련도를 추정하지 않음 |

# 레이아웃 제안
- 첫 화면 중앙: 날짜별 충원판. 빈자리에서 바로 후보를 열어 연락한다. 카드에는 부족 인원·마감 시점·추천 다음 행동을 우선 노출한다.
- 오른쪽(모바일은 위쪽): 내가 결정할 일. ‘반납 완료시간 확인 → 공고 수정 후 답변’, ‘선탑 희망자 → 통화해 일정 기록’처럼 이유와 행동을 함께 제공한다.
- 하단: AI가 처리한 내용 요약. 상세 원문·근거·변경 이력은 펼쳐서 확인하며 처리한 일은 미해결 배지에서 제거한다.
- 지원자 상세: 대화와 진행 기록을 나란히 연결하고, 전화 후 20초 내 다음 행동을 남길 수 있게 한다. 모든 기능을 거대한 공고 모달에 계속 추가하지 않는다.

# 구현 경계 — 후속 연락 연결
- 날짜별 충원판은 공고 모집인원을 기준으로 비교한다. 일별 실제 운행 여부·필요 인원 입력은 다음 필수 작업이다.
- 후보 카드의 연락 간편 편집에서 최근 연락 결과·담당자·다음 할 일·예정일을 관리하고, 미완료/오늘까지/완료·담당자로 찾는다. 실제 선탑·백업 이력과 날짜별 확정은 기존 준비 기록에 별도로 유지한다.
- 연락 기록은 관리자가 입력한다. AI가 이 새 기록을 근거로 중복 질문을 줄이는 응대 연결은 별도 검토·회귀가 필요하다.

# 창의적 실험
- ‘내일 이 사람이 못 나오면?’: 실제 예비 후보·가용성과 빈자리를 보여주는 시나리오. 가상 배정을 저장/통지하지 않으며 관리자가 비교만 한다.
- ‘인수인계 카드’: 담당자가 바뀌어도 마지막 약속·미정 조건·다음 연락만 한 화면으로 전달한다. AI 요약에는 원문 확인 버튼을 붙인다.
- ‘지금 딱 하나만’: 가장 급한 충원 결정을 한 건 추천하고 근거·대안을 함께 제공한다. 관리자는 순서와 담당자를 바꿀 수 있다.

# 운영에서 확인할 것
- 기존 관심자 후속 연락은 관리자가 실제 첫 상차지·연결 프로와 직접 조율한다.
- 미분류 수거 문의는 공고·배송지 연결이 없어 수거 여부를 확정할 수 없다. 라인 확인 후 채용 문의와 운행 문의를 구분할 필요가 있다.
- 대화량보다 충원한 라인·일자 수, 확정까지 걸린 시간, 관리자 개입 횟수, 잘못 안내한 문자, 선탑 후 실제 투입을 본다.
