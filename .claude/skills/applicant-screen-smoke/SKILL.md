# 지원자 화면 스모크 (Playwright MCP)

이 화면은 **시니어(50~70대)가 문자로 받은 링크를 눌러 보는 유일한 접점**이고 테스트가
없다. 코드 읽기로는 "화면에 누를 것이 하나도 없는 상태"를 놓친다 — M4에서 실제로 났다.
`/p/[token]` 또는 그 데이터를 만드는 코드를 고쳤으면 이 절차를 돈다.

## 준비

1. `npm run dev`(3000)을 띄운다. 프로덕션 URL로 하지 않는다 — 관심 버튼을 누르면
   **실제 `job_candidates` 행과 문자 발송 대상이 생긴다.**
2. 토큰은 `applicants.access_token`(UUID). 검증용으로 고를 때 조건을 명시해서 뽑는다:
   ```sql
   -- 예: 차량 없음 + 좌표 없음(가장 잘 깨지는 조합)
   select access_token from applicants
   where own_vehicle in ('없음','아니오') and lat is null limit 1;
   ```
   토큰은 개인 식별 접근키다 — 커밋·문서·PR 본문에 남기지 않는다.

## 확인 항목 (전부 눈으로)

- **누를 것이 있는가** — 헤더가 "[관심 있어요]를 눌러주세요"라고 말할 때 그 버튼이 화면에
  실제로 보이는가. 활성 카드가 전부 접힌 그룹으로 들어가 회색 점선 버튼만 남는 상태가
  대표적 사고다.
- **그룹 배치** — 이야기 중·접수됨 카드가 "조건이 다를 수 있는 자리" 접힌 그룹에
  들어가 있지 않은가(본인이 진행 중인 자리가 화면에서 사라지면 안 된다).
- **문구 진실성** — 종료·보류 카드에 "연락드릴게요"가 남아 있지 않은가. 금지어(확정·배정·
  합격·출근)가 없는가.
- **60초 갱신** — 카드를 읽는 상태로 70초 이상 두고, 카드가 위치·그룹을 옮기지 않는지 본다.
  (`browser_wait_for` 로 대기 → `browser_snapshot` 을 전후 비교)
- **오클릭 방지** — 관심은 2단계 확인인가, 전송 중 버튼이 잠기는가, 마감된 카드에 확인
  패널이 열려 있지 않은가.
- **큰 글씨·큰 버튼** — `browser_resize`로 375×667(작은 폰)에서 버튼이 잘리거나 겹치지 않는지.

## 마무리

스냅샷에서 본 사실만 보고한다. "정상으로 보인다"가 아니라 **어떤 카드가 몇 장, 어느
그룹에, 어떤 문구로 보였는지** 적는다. 관심 버튼을 눌러본 경우 로컬 DB에 남은 행을
정리했는지도 함께 남긴다.
