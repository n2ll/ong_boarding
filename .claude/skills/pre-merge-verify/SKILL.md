# 커밋 전 검증 (테스트 없는 레포용)

AGENTS.md 작업 4원칙 #4의 실행 절차. 테스트 스위트가 없으니 **검증 가능한 성공 기준**을
매번 손으로 만든다. "빌드 통과"만으로 보고하지 않는다.

## 1. 기계 검증

```
npx tsc --noEmit      # strict — 타입 안전망이 실제로 작동했는지
npm run build         # App Router 라우트 수집·번들 에러
```

## 2. 로직은 진짜 코드로 재현한다 (손으로 옮겨 적지 않는다)

파서·판정 함수를 고쳤으면 **그 TS 파일을 컴파일해서 프로덕션 행 전체에 돌린다.**
의사코드를 손으로 포팅해 검증하면 포팅 실수를 검증한 것이 된다.

```
npx tsc lib/<파일>.ts --outDir /tmp/verify --module commonjs --target es2020
# 그 뒤 node로 프로덕션에서 뽑은 실제 값 배열을 통과시켜 before/after를 비교
```

기준: **바뀐 행의 개수와 방향**을 말할 수 있어야 한다. 예 — "슬롯 확정 406 / 미확인 239",
"반경 15km에서 190↔296명". 숫자가 없으면 검증한 게 아니다.

## 3. 영향 경로 손계산

바꾼 화면·API를 실제 사용 흐름으로 한 번 걸어본다. 특히:
- 지원자 쪽(무로그인 `/p/[token]`)에서 **버튼이 0개가 되는 상태**가 생기는가.
  (M4에서 실제로 났다 — 전원 warn이면 활성 카드가 전부 접혀 화면에 누를 것이 없었다.)
- 60초 백그라운드 갱신이 읽는 중 카드 위치·그룹을 바꾸는가(시니어 오클릭 금지).
- 매니저 쪽에서 이 변화가 **보이는가** — 지원자만 깨지고 매니저 화면은 정상인 사고가 두 번 났다.

## 4. 문구 점검 (절대 규칙)

새로 추가·수정한 사용자 문구 전부에서:
- 금지어 — `확정` `배정` `합격` `출근` `시작하세요`. 관심·대화·정보 제출은 확정이 아니다.
- **거짓 약속 금지** — 보류·종료 상태에 "연락드릴게요"를 붙이지 않는다(오지 않는 연락을
  기다리게 만든다). 실패 토스트의 사유가 실제 사유와 일치하는지 확인한다("이력이 없습니다"가
  사실은 노출 탈락이었던 사고가 있었다).

## 5. 마이그레이션·시크릿

- SQL은 `docs/migrations/YYYY-MM-설명.sql`로 **새 파일 추가만**. 기존 파일 사후 수정 금지.
- 프로덕션에 적용했으면 적용 사실을 커밋 메시지·문서에 남긴다.
- `.env.local` 밖으로 실제 값이 나가지 않았는지 diff에서 확인한다.

## 6. 보고

실무자 입장(화면·클릭·겪는 결과)으로 먼저 쓰고, 파일·API 상세는 맨 뒤에 분리한다.
건너뛴 것이 있으면 무엇을 왜 건너뛰었는지 명시한다.
